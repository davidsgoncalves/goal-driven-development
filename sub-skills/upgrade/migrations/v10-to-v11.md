# Migração v10 → v11

## Objetivo

A v11 inverte a ordem `init` ↔ `spec` no fluxo single-task, espelhando o que `init-tree` já faz em batch:

- **v9/v10:** `spec → init → plan → implement → pack-up`. Init exigia spec existir.
- **v11:** `init → spec → [publish-spec] → plan → implement → pack-up`. Init é puramente estrutural (cria pasta vazia); spec roda depois e atualiza o status.md.

A motivação: init nunca tocou git (sempre foi só bookkeeping), então a "spec-first como gate" da v9 era cerimonial. Trocar a ordem traz simetria com `init-tree`, permite `status` mostrar a task desde o init, e simplifica o state machine eliminando o flag `--type=trivial`.

Mudanças estruturais:

- **`init` reescrito** — vira entry point estrutural. Cria `GOD/tasks/{cod}/` com `plan.md` vazio + `status.md` (`phase: initialized`, `spec_path: null`). Não exige spec, não toca git, não busca dados externos.
- **`init --type=trivial` removido** — flag morta. Substituído por `init --profile=trivial` (label informativa no status.md, sem mudar comportamento da skill). Trivial salta spec/plan e vai direto pro implement.
- **`spec` ganha auto-init silencioso** — se status.md não existe (usuário invocou spec direto, hábito v9), spec roda init programaticamente. Atualiza status.md pra `phase: specified` após escrever spec.
- **`init-tree` reescrito** — não escreve mais specs em batch (gerar rascunho sem Q&A produzia lixo). Cria pastas de contexto + estrutura de execução vazia por folha (`phase: initialized`). Usuário escreve cada spec individualmente com `spec {cod}`.
- **`implement` detecta fluxo trivial** — se `phase: initialized + profile: trivial`, pula leitura de spec/plan e resolve branch sozinho.
- **`update-spec` ajusta pré-requisito** — agora exige `phase ≥ planned`. Pra mudança em fase `specified` (antes do plan), use `spec --review-feedback`.
- **Phase `initialized` volta ao state machine** — entre `init` e `spec`. Era legacy de v5/v6, agora é estado normal v11.

## Arquivos afetados

- `GOD/VERSION` — conteúdo muda de `v10` para `v11`

**Inalterados (nenhuma reescrita automática):**
- `GOD/config.md`
- `GOD/knowledge.md`
- `GOD/patterns.md`
- `GOD/learned-patterns.md`
- `GOD/hooks.md`
- `GOD/tasks/` (todas as tasks v9/v10 — `status.md`, `description.md`, `plan.md`, `changelog.md`, `coverage.md`)
- `GOD/tasks/.archived/` (se existir)
- `<specs_path>/` (specs existentes intactas)

**Mudanças de contrato (não de arquivos):**
- `init` reescrito (entry point estrutural).
- `spec` reescrito (auto-init silencioso + escrita em status.md).
- `init-tree` reescrito (não gera specs em batch).
- `implement` ganha passo 1.5 (detecção de fluxo trivial).
- `update-spec` ajusta pré-requisito de fase.
- `status`, `resume`, `doctor` atualizados pra refletir phase `initialized` como estado normal v11.

## Riscos conhecidos

- **Tasks v9/v10 em `phase: specified`, `planned`, `implementing`, `implemented` ou `packed-up`** — continuam funcionando intactas. Status.md já tem todos os campos que o fluxo v11 espera (`phase`, `profile`, `spec_path`, etc.). Nenhuma reescrita necessária.
- **Tasks v9 inicializadas com `--type=trivial`** — status.md tem `phase: planned` (atalho v9 pra pular spec). Continua funcionando: implement ainda lê plan.md vazio + branch null e pode resolver. **Atenção:** essas tasks **não** caem no caminho novo de detecção de trivial (passo 1.5 do implement v11), porque `phase` é `planned`, não `initialized`. O caminho legacy continua válido — implement detecta plan.md vazio + branch null e sugere ao usuário rodar `plan` ou aceitar resolver branch manualmente.
- **Tasks legacy v8 com `description.md`** — continuam compatíveis. Spec lê `description.md` por retrocompat (caso C do passo 0.5 do spec); init preserva o arquivo se existir (passo 3.5 do init).
- **Hábito v9 do usuário (rodar `spec` primeiro)** — coberto pelo auto-init silencioso. Spec detecta status.md ausente e roda init programaticamente. Pro usuário, experiência igual à v9.
- **Init-tree v10 que gerava specs em batch** — mudança quebra a expectativa de quem usava com `--refresh` ou esperava specs rascunho. Nenhuma migração de dados — pastas de contexto e specs existentes ficam onde estão. Re-rodar `init-tree {epic}` v11 vai apenas adicionar folhas novas (sem reescrever).
- **Nenhum risco de perda de dados.** Migração só atualiza VERSION; nenhum arquivo é removido nem reescrito.

## Passos da migração

### 1. Verificar pré-condições

- Confirmar que `GOD/VERSION` existe e contém `v10`.
- Se não existir ou estiver em versão anterior, abortar — o usuário deve rodar as migrações anteriores primeiro.

### 2. Atualizar VERSION

Sobrescrever o conteúdo de `GOD/VERSION` com:

```
v11
```

### 3. Não tocar em tasks ativas

A migração **deliberadamente não modifica** nenhum arquivo dentro de `GOD/tasks/{cod}/` ou `<specs_path>/`. As mudanças (init reescrito, spec auto-init, init-tree estrutural, implement detectando trivial) só atuam em execuções futuras.

Tasks já em `phase ∈ {specified, planned, implementing, implemented, packed-up}` continuam fluindo normalmente — o state machine v11 é superconjunto do v10 (adiciona `initialized` antes de `specified`).

### 4. Relatório final

```
✅ Migração v10 → v11 concluída!

VERSION atualizado: v11

Nenhum arquivo modificado além do VERSION.

Mudanças no fluxo:
  📁 init                     — entry point estrutural (cria pasta vazia, phase: initialized)
  📐 spec                     — auto-init silencioso + escrita em status.md (phase: specified)
  🌲 init-tree                — não escreve mais specs em batch; cria pastas de execução vazias por folha
  🔧 implement                — detecta fluxo trivial (phase: initialized + profile: trivial)
  ⏭️  --type=trivial removido  — substituído por --profile=trivial (label informativa)
  🔁 update-spec              — agora exige phase ≥ planned

Tasks em andamento continuam compatíveis. State machine v11 = superconjunto v10.

Próximos passos sugeridos:
  - Pra tasks novas, comece com `init {cod}` e siga `spec` → `plan` → `implement` → `pack-up`.
  - Pra task trivial: `init {cod} --profile=trivial` e pule direto pro `implement`.
  - Hábito v9 (rodar `spec` direto) continua funcionando — auto-init silencioso cobre.
```
