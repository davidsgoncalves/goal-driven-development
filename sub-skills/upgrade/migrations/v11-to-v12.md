# Migração v11 → v12

## Objetivo

A v12 entrega três funcionalidades novas componíveis sobre o fluxo existente:

- **Flag `--auto`** em `init` e `init-tree` — encadeia spec → plan → implement → pack-up sem gates. Abre worktree com symlink de `node_modules`. Em falha irresolúvel, para e chama humano.
- **Flag `--stack`** em `init` e `init-tree` — lê `is blocked by` no Jira, monta DAG topo-sortado, grava `stack_parent`/`stack_order`/`stack_depth` em `status.md`. `plan` usa branch do parent como `branch_base`; `implement` faz cascata de rebase. PRs sempre abertos em draft contra `main`.
- **Step novo `ready`** (sub-skill) — pós-pack-up: tira PR de draft via `gh pr ready` + adiciona reviewers de `GOD/config.md`. Sempre manual. Modo recomendação (sem arg) cruza `stack_parent` com estado dos PRs e propõe lista em batch.
- **Sub-skill nova `spec-tree`** — Q&A unificada em batch pra gerar N specs em uma sessão. Usada por `init-tree --auto`.

Composições:

- `init PROJ-123 --auto` — single task, ciclo full automático.
- `init PROJ-123 --stack` — single task que depende de outra task GOD em andamento, branch sai dela.
- `init-tree PROJ-100 --auto --stack` — árvore inteira em modo autopilot com branches empilhadas.

## Arquivos afetados

**Atualizado:**
- `GOD/VERSION` — conteúdo muda de `v11` para `v12`
- `GOD/config.md` — adiciona seção `## reviewers` no final (lista vazia por default)

**Inalterados:**
- `GOD/knowledge.md`
- `GOD/patterns.md`
- `GOD/learned-patterns.md`
- `GOD/hooks.md`
- `GOD/tasks/` (todas as tasks existentes continuam funcionando — campos novos do v12 são opt-in)
- `<specs_path>/` (specs existentes intactas)

**Mudanças de contrato (não de arquivos):**
- `init` aceita `--stack` e `--auto`.
- `init-tree` aceita `--stack` e `--auto`.
- `plan` resolve `branch_base` da branch do `stack_parent` quando presente.
- `implement` faz cascata de rebase antes de codar quando `stack_parent` presente.
- `ready` (sub-skill nova) disponível no fluxo.
- `spec-tree` (sub-skill nova) disponível pra Q&A em batch.

## Riscos conhecidos

- **Tasks existentes sem `stack_parent`** — comportamento idêntico ao v11. Os campos novos no `status.md` são opcionais; ausência = task independente.
- **`GOD/config.md` sem `## reviewers`** — esta migração adiciona a seção vazia. Comportamento: `ready` roda sem reviewers até o usuário preencher.
- **Rebase em cascata pode dar conflito** — quando aplicável. Conflito irresolúvel pausa a task e chama humano via `paused: true` + bloco `⏸ PAUSE` no `changelog.md`. Sem perda de trabalho.
- **`--auto` em árvore grande gasta tokens** — Q&A é em batch (uma sessão), mas o loop plan/implement/pack-up roda spec por folha. Considere usar `--auto` em árvores de 3–8 folhas; acima disso talvez compense rodar manualmente pra revisar entre folhas.
- **`gh pr ready` em PR não-draft** — falha silenciosa. `ready` detecta via `gh pr view` antes de tentar.
- **Nenhum risco de perda de dados.** Migração toca apenas `VERSION` e adiciona seção no `config.md`.

---

## Passos da migração

### 1. Verificar pré-condições

- Confirmar que `GOD/VERSION` existe e contém `v11`.
- Se não existir ou estiver em versão anterior, abortar — o usuário deve rodar as migrações anteriores primeiro.

### 2. Atualizar VERSION

Sobrescrever o conteúdo de `GOD/VERSION` com:

```
v12
```

### 3. Adicionar seção `## reviewers` ao `GOD/config.md`

Ler `GOD/config.md`. Se já contém uma seção `## reviewers` (instalação manual antecipada), pular. Caso contrário, **anexar ao final** do arquivo:

```markdown

## reviewers

(v12) Lista de GitHub handles que a skill `ready` adiciona como reviewers do PR ao tirar de draft.
Um handle por linha, sem `@`. Linhas vazias e linhas começando com `#` são ignoradas.

(deixe vazio pra `ready` rodar sem adicionar reviewers — só tira de draft)

```
# alice
# bob
# carol
```

> Cenários:
> - Time pequeno: 1-3 handles fixos, sempre os mesmos
> - Round-robin: usuário gerencia manualmente comentando/descomentando linhas
> - Sem reviewers automáticos: deixe vazio, `ready` apenas tira de draft
```

### 4. Não tocar em tasks ativas

A migração **não modifica** nenhum arquivo dentro de `GOD/tasks/{cod}/` ou `<specs_path>/`. As funcionalidades novas (auto, stack, ready) só atuam quando ativadas via flag em execuções futuras.

Tasks já em `phase ∈ {specified, planned, implementing, implemented, packed-up}` continuam fluindo normalmente — campos novos do v12 (`stack_parent`, `stack_order`, `stack_depth`, `ready`, `ready_at`, `ready_reviewers`) são opcionais e ausentes nelas, o que é comportamento esperado.

### 5. Relatório final

```
✅ Migração v11 → v12 concluída!

VERSION atualizado: v12
GOD/config.md: seção `## reviewers` adicionada (vazia por default)

Funcionalidades novas:
  ⚡  init --auto               — ciclo full sem gates (até pack-up); abre worktree
  🌲 init-tree --auto           — autopilot pra árvore inteira via spec-tree
  📚 init --stack / init-tree --stack — branches empilhadas via DAG do Jira
  ✅ ready (sub-skill)          — tira PR de draft + adiciona reviewers (manual, opt-in)
  📐 spec-tree (sub-skill)      — Q&A em batch pra múltiplas folhas
  🔧 plan + implement           — cascata de rebase quando stack_parent presente

Tasks existentes 100% compatíveis. Flags são opt-in.

Próximos passos sugeridos:
  - Preencha a lista de reviewers em `GOD/config.md` (seção `## reviewers`)
  - Pra testar autopilot: pegue uma task pequena e rode `init {cod} --auto`
  - Pra testar stack: monte 2 tasks no Jira com `blocks`/`is blocked by` e rode `init-tree {raiz} --stack`
  - Para tasks novas single-task que não precisam de stack/auto, fluxo v11 continua igual
```
